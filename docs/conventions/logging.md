# 로깅

로그를 추가하거나 요청 추적·로그 형식을 바꿀 때 읽는다.

## 요청 추적

- `global/logging/MdcLoggingFilter`가 모든 요청의 맨 앞에서 16자리 `traceId`를 만들어 MDC에 넣고, 응답 헤더 `X-Trace-Id`로 돌려준다.
- 요청이 끝나면 `메서드 경로 상태코드 처리시간` 한 줄을 INFO로 남긴다. 쿼리 문자열은 기록하지 않는다.
- 로그 패턴(`application.yml`의 `logging.pattern.level`)이 모든 로그에 `[traceId=...]`를 붙인다. 요청 밖(시작·스케줄러 등)의 로그는 비어 있다.
- 클라이언트가 오류를 제보하면 `X-Trace-Id` 값으로 서버 로그에서 해당 요청을 찾는다.

## 로그 레벨

| 레벨 | 쓰는 때 |
| --- | --- |
| `ERROR` | 예상하지 못한 예외. 스택을 함께 남긴다 (`GlobalExceptionHandler`) |
| `WARN` | `CustomException` 같은 처리된 비즈니스 실패. 오류 코드와 경로만 남긴다 |
| `INFO` | 요청 완료, 외부 API 호출 결과처럼 흐름 확인에 필요한 정보 |
| `DEBUG` | 로컬 디버깅용. 운영에서 켜 두지 않는다 |

## 기록하지 않는 것

- 토큰·쿠키·`Authorization` 헤더, 비밀번호, API 키
- 요청·응답 본문 전체, 일기 내용 같은 사용자 작성 내용
- 이메일 등 개인정보. 필요하면 사용자 ID로 대신한다
- 외부 API 응답 본문 전체. 상태 코드와 필요한 식별자만 남긴다
