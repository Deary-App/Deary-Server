# Deary 이슈와 브랜치

## 트리거와 실행 범위

- **"이슈 만들어줘"**: 기존 이슈를 먼저 확인하고 필요할 때만 생성한다. 브랜치는 자동 생성하지 않는다.
- **"이슈 확인해줘"**: 연결된 이슈의 제목·상태·URL만 확인한다. 이슈나 브랜치를 생성하지 않는다.
- **"브랜치 만들어줘", "브랜치로 checkout해줘"**: 확인된 기존 이슈에 연결된 브랜치 생성·checkout만 한다. 이슈를 자동 생성하지 않는다.
- **"새 작업 준비해줘", "이슈와 브랜치 준비해줘"**: 이슈 확인·필요 시 생성 후 연결 브랜치 생성·checkout까지 한다. 구현·커밋·푸시·PR로 이어가지 않는다.
- 위 명령이 없는 구현·커밋 요청에서는 이 스킬로 GitHub 이슈나 브랜치를 만들지 않는다.

## 실행

1. [Git 규칙](../../../../docs/conventions/git-convention.md)의 Prefix·이슈·브랜치 항목과 `git status --short --branch`를 확인한다. 요청·브랜치·열린 이슈를 대조해 같은 작업의 이슈가 있는지 먼저 찾는다. 번호가 있으면 실제 제목과 상태를 확인하고 재사용한다.
2. 새 이슈가 필요하면 기능·설정·문서는 `.github/ISSUE_TEMPLATE/feature.md`, 버그는 `bug.md` 형식을 쓴다. 제목은 `[prefix] 한국어 설명`이고 버그는 `[fix]`로 시작한다. 본문에는 해야 할 일과 이유, 완료를 판단할 Todo를 적는다.
3. 담당자는 요청한 사람 또는 사용자가 지정한 사람으로 한다. 작업 유형·팀원 라벨은 자동 라벨 워크플로가 붙이므로 중복 지정하지 않는다. 워크플로가 아직 저장소 기본 브랜치에 없으면 같은 라벨을 직접 지정한다.
4. 인증된 `gh` CLI로 이슈를 **한 번** 생성하고 URL·번호를 확인한다. 응답이 불명확하면 이슈 목록을 먼저 조회한다. 권한이 없으면 이슈 초안을 보고하고 생성을 완료한 것처럼 말하지 않는다.
5. 브랜치 명령이 있으면 이슈의 Development에 연결된 브랜치가 있는지 먼저 확인한다. 있으면 그 브랜치를 checkout한다. 없고 작업 트리가 안전하면 `<prefix>/#<번호>-<요약>`으로 정하고 `gh issue develop <번호> --base develop --name '<브랜치명>' --checkout`으로 만든다. 요약은 영문 키워드 1~4개, 소문자·하이픈, 30자 이내다.
6. `git branch --show-current`로 전환을 확인한다. 기존 작업 브랜치와 미커밋 변경은 임의로 옮기거나 덮어쓰지 않는다. 추가 `git push`는 하지 않는다.
7. 확인·생성한 이슈 URL과, 브랜치 명령이 있었다면 현재 브랜치명을 보고하고 멈춘다.
